# 找回本地资料

`search_local` 搜索指定目录中的 UTF-8 文本，返回路径、位置和每段最多 200 个字符的命中上下文。关键词不区分大小写，采用 Unicode casefold 子串匹配，保留中文与代码标点的字面含义。默认 `result_mode="lines"` 按命中行返回；`result_mode="files"` 每文件返回一条，并按命中字段排序。默认仍返回文本。

## 按文件找回资料

```json
{
  "query": "asyncio",
  "root": "F:/research",
  "result_mode": "files",
  "max_results": 5,
  "response_format": "json"
}
```

文件模式适用于同一份日志或长笔记产生很多命中、占满原有结果上限的情况：每份文件只占一个名额，继续扫描预算允许的范围，再选择前 N 份。

排序采用离散优先级：**有效笔记元数据标题 → 标签 → 文件名 → 文件全文**。只看最高优先级的命中字段，不按重复行数加分；相同级别按相对路径的 Unicode casefold 排序，再按原路径打破大小写平局。因此，后扫描到的标题匹配笔记也可以替换先保留的普通全文匹配。标题和标签使用完整的已解析字段，不受输出预览截断影响；未识别的 frontmatter 仍可作为普通文本匹配，但不提供这些排序字段。

默认 `query_mode="literal"` 把关键词作为一个完整子串：`asyncio timeout` 按这段连续文本匹配。文件模式也可以匹配正文中没有出现的文件名，或 JSON 转义前的标题／单个标签。目录名不参与关键词匹配；文件仍需符合扩展名、大小、UTF-8 和元数据筛选条件。

每项额外返回 `matched_fields`（`title`、`tags`、`filename`、`text`）、`matched_lines` 和 `preview_source`。`text` 字段的搜索范围是整个文件，包括 frontmatter；行数是完成匹配检查的文件中命中的行数，不是出现次数。预览优先使用第一条命中行；仅标题、标签或文件名匹配时使用该字段，`line=null`，不会编造文件行号。纯筛选浏览仍每文件一条，按相对路径排序，`line` 与 `column` 都是 `null`。

扫描只保留最多 `max_results` 份候选的预览和元数据，不积累全部命中正文，不创建索引。相比按行模式的提前停止，文件模式通常读取更多文件，耗时也可能更长。

## 多个关键词

记得几个词但不记得原句时，指定 `query_mode="all"`；例如标题是“asyncio 指南”、正文讨论“任务取消”，可以这样找回：

```json
{
  "query": "asyncio 取消",
  "root": "F:/research",
  "result_mode": "files",
  "query_mode": "all",
  "response_format": "json"
}
```

| `query_mode` | 匹配方式 |
|---|---|
| `literal`（默认） | 原有整段子串匹配，包括查询首尾空格和标点 |
| `all` | 按 Unicode 空白拆分，要求全部词命中，顺序不限 |
| `any` | 同样拆词，只要任一词命中 |

多词模式每个词仍采用 Unicode casefold 子串匹配。大小写等价的重复词只检查一次，保留首次拼写；例如 `STRASSE Straße` 是一个要求。总查询最多 4096 个字符，最多 16 个不同词，每词预览最多 200 个字符。全空白查询沿用原有规则：必须有元数据筛选，按纯筛选浏览。

`files` 在同一文件内聚合匹配：有效标题、各个标签、文件名和全文可以分别提供某个词；全文仍包括 frontmatter。`lines` 只检查文件文本，`all` 要求所有词在同一行，`any` 返回含任一词的行。两者都不跨文件拼凑条件。`matched_lines` 在文件模式中表示含任一查询词的行数，同一行只计一次。

这是明确的空白拆词，不是自然语言分析：中文多个词需用空白隔开，例如 `取消 超时`。`C++`、`--flag`、`foo.bar()`、引号和反斜杠都保留字面意义。没有引号短语、减号排除、通配符或 AND／OR 操作符；要匹配一整段含空格的文字，继续使用 `literal`。文件名包含空格时也不会被拼成短语条件。

排序仍使用标题、标签、文件名、全文四个层级。在 `all` 模式中，先为每个词找出它命中的最高层级，再以其中最低者作为整个查询的排序层级：全部词都在标题中才算标题级；一个词在标题、另一个只在正文，则是全文级。`any` 使用任一命中词的最高层级。相同层级仍按相对路径排序，不按命中次数或覆盖词数加分。

JSON 返回 `query_mode`，多词模式还返回拆分去重后的 `query_terms`。每个多词命中附：

- `matched_terms`：实际找到的查询词，沿用输入次序；`any` 可以只包含一部分。
- `term_matches`：每词一份首次命中上下文，含 `term`、`preview_source`、`line`、`column` 和原文切片位置。优先使用全文中最早的命中行；仅解码字段或文件名命中时用该字段，行号为 `null`。这些片段支持核对查询条件，不保证包含完整长词。
- `rank_field`：仅文件模式返回整个查询用于排序的层级。`matched_fields` 仍列出任何词曾命中的全部字段，不等同于排序层级。

原有顶层 `text`、`line` 等预览字段继续保留，文件模式优先展示最早命中行，同一行用位置最靠前的词。文本输出分别列出每词上下文，避免只展示第一个词而无法核对其他条件。多词匹配和生成上下文都检查现有时间／取消预算，未完成检查的文件不会进入排名。

## 按笔记信息筛选

例如，搜索 Python 集合中同时标有 asyncio 和 MCP、来源属于 python.org 的笔记：

```json
{
  "query": "取消",
  "root": "F:/research",
  "include_ext": "md",
  "collection": "Python",
  "tags": "asyncio, MCP",
  "source_domain": "python.org",
  "response_format": "json"
}
```

- `collection` 比较笔记元数据中的原始集合名，不是保存时清理过的文件夹名；忽略首尾空白和大小写。
- `tags` 用逗号分隔，要求全部精确匹配，忽略大小写。
- `source_domain` 接受裸域名，包含其子域名；`docs.python.org` 可以匹配 `python.org`，`python.org.evil.example` 不可以。只检查元数据里的 HTTP(S) 来源链接，不搜索正文里的域名，也不访问网络。
- 多个条件同时生效。`query` 留空或全为空白时，必须至少设置一个筛选条件，每份笔记返回一条，`line` 为 `null`。
- 有关键词时，按行模式搜索整个文本（包含 frontmatter），按命中行计数；文件模式还检查文件名和解码后的标题／标签。没有元数据的普通文件仍可搜索。

筛选读取 `save_finding` 当前生成的 `.md` 文件头：`---` 包围，字段值使用 JSON 字符串或字符串数组。这些值也是合法 YAML，但本工具**不是通用 YAML 解析器**；手写裸字符串、YAML 多行值、重复字段或未闭合头部不能用于筛选。头部必须在前 257 行内闭合；无法解析时报告 `skipped.metadata`，不执行 YAML 标签或对象构造。原文件不会修改。

## 范围和资源控制

| 参数 | 默认值 | 说明 |
|---|---|---|
| `max_results` | 50 | 1–1000；lines 达到上限即停止，files 只限制返回文件数 |
| `result_mode` | `lines` | `lines` 按行返回；`files` 每文件一条并按字段优先排序 |
| `query_mode` | `literal` | `literal` 整段子串；`all` 全部词；`any` 任一词；后两种按空白拆分，最多 16 个不同词和 4096 字符 |
| `include_ext` | 原有文本与代码扩展名 | 逗号分隔，可带点；空字符串表示所有普通文件 |
| `exclude_dirs` | `.git,node_modules,__pycache__,.venv,venv,.next,dist,build,.godot` | 按目录名忽略大小写，在进入前排除；自定义值覆盖默认值，空值取消目录名排除 |
| `max_entries` | 100000 | 文件和目录条目总数，最大 1000000；被排除目录内部不计数、不遍历 |
| `max_file_bytes` | 2097152 | 单文件默认 2 MiB，最大 16 MiB；分块读取，超大文件不返回部分命中 |
| `time_budget_seconds` | 10 | 大于 0、最大 600；在遍历、读取块和逐行匹配间检查 |

目录名排除只作用于根目录内遇到的子目录。用户直接指定名为 `build` 的根目录时仍可搜索。扩展名以外的文件、符号链接、Windows reparse point（含目录联接和部分云占位文件）及特殊文件属于搜索范围之外；不会跟随这些链接。不会加载 `.gitignore`，不支持目录路径或 glob 排除表达式。

正文仅接受 UTF-8／UTF-8 BOM。含 NUL、非法 UTF-8、超大或无法读取的文件会被跳过并计数，不再静默丢掉坏字节。目录无法读取也会计入 `io_errors`。

文件工作在线程中执行，MCP 主循环可以继续处理其他请求。取消会通知扫描停止并等待线程结束，重复取消也不会丢下仍在扫描的线程。同步文件系统调用本身无法强制打断；慢网盘、磁盘故障或系统调用卡住时，返回与取消可能超过预算。此机制不是严格墙钟时限，也不是针对恶意并发路径替换的文件系统沙箱；应搜索受信任的本地目录。

## JSON 和完整性

成功执行返回 `ok: true`、`result_mode`、`query_mode`、`matches`、`complete`、`stop_reason`、`stats`、`skipped`、`filters`、`elapsed_seconds`。参数或根目录错误返回 `ok: false` 与 `error`。

`ok` 表示工具执行成功，不等于完整搜索。按行模式达到匹配上限、条目上限或时间预算时，`stop_reason` 分别为 `max_results`、`max_entries`、`time_budget`，保留已有命中。超大、二进制、编码错误、读写错误，或筛选时遇到无法解析的元数据，也使 `complete` 为 `false`。这时不能用空结果判断资料不存在。

文件模式另外区分扫描与展示：

- `scan_complete`：声明范围是否完整扫描，沿用跳过错误对完整性的影响。
- `matched_files`：已完成匹配检查的文件中，共发现多少份命中；扫描不完整时只是当前计数。
- `results_truncated`：已发现的命中文件多于返回条数。它为 false 不表示未扫描部分没有其他命中。
- `complete`：只有扫描完整且所有已发现命中都已返回时才为 true。完整扫描后只取前 N 份时，`scan_complete=true`、`results_truncated=true`、`complete=false`，`stop_reason=null`，因为扫描没有提前停止。

文件模式到达时间或条目预算时，保留已完成文件中的最佳结果，不能声称是整个目录的最佳结果；匹配检查尚未完成的文件不加入候选。

主动排除目录、扩展名、链接和特殊文件不使 `complete` 变为 `false`；完整性只针对声明的范围。没有筛选时，头部不规范不妨碍全文搜索。每个命中附元数据预览：来源最多 2048 字符，其他字符串字段最多 256 字符，标签最多 32 个、每个 64 字符；截断用 `metadata_truncated` 标明，筛选仍使用完整字段。

扫描使用文件系统返回的顺序。按行模式保持该顺序；文件模式在已检查范围内按上述规则排序。扫描不完整时，遍历顺序会影响哪些文件被检查，返回集合可能不同。两种模式都没有续页游标。每次读取当前文件，不持久化索引或缓存；保存、修改和删除在下一次调用中可见。正在修改的目录不具有快照一致性。Python 代码可用 `from mcp_harries_resourcer import server`，直接调用 `server.search_local` 需 `await`；MCP 调用方式不变。

## 命中上下文和位置

预览围绕首个命中截取，最多 200 个 Unicode 字符，通常保留前方 60 字符；长查询优先展示查询的起始部分。保留源文字的空白。`column` 是原始行或字段内从 1 开始的字符列；`text_start`、`text_end` 是预览在该行或字段内从 0 开始、右端不包含的位置，`source_chars` 是其完整字符数，`text_truncated` 表示有内容未显示。查询超过 200 字符时不能展示整个查询。

`Straße` 与 `STRASSE` 这类 casefold 展开仍按原文计算列号。文本输出用省略号标记被截掉的一侧；JSON 的 `text` 直接对应原文切片，不附加省略号。

## 依据与验证

目录排除借鉴 [官方 Filesystem MCP 的搜索实现](https://github.com/modelcontextprotocol/servers/blob/main/src/filesystem/lib.ts) 的遍历前剪枝思路；该项目搜索文件名，本项目继续搜索文件内容。使用 [Python scandir](https://docs.python.org/3/library/os.html#os.scandir) 逐目录枚举并及时关闭句柄，实现独立编写，没有引入搜索服务或额外依赖。

回归覆盖保存后的组合筛选、来源域名边界、纯筛选浏览、修改与删除、坏编码、文件读取时增长、目录剪枝、显式根目录、数量／时间限制和重复取消。真实 MCP 子进程验证保存 → 筛选 → 修改 → 再搜索 → 删除；Windows 验证实际目录联接，Linux CI 验证符号链接与循环链接。

早期元数据筛选批次本地运行 193 项测试，192 项通过、1 项因 Windows 符号链接权限不足跳过，实际目录联接测试通过。期间发现已有批量缓存清理测试的 30 毫秒调度窗口偶发过短，改用 1 秒窗口，并增加慢任务启动、取消完成、超时状态与未完成 URL 断言；生产网络预算不变。四组跨平台发布结果以 [Actions](https://github.com/fisHarly0/mcp-harries-resourcer/actions/workflows/tests.yml) 为准。

生成目录基准：`python scripts/local_search_benchmark.py --output <结果.json>`。先把 `TEMP`／`TMP` 指向所需临时盘；脚本生成 1000 个笔记和排除目录内的 10000 个文件，交替运行四轮旧遍历方式与新版，核对命中一致。结果用于判断此样本的成本，不代表所有磁盘或真实资料库的表现。

2026-10-04，Windows / Python 3.12.12 / F 盘测量：旧方式四轮为 0.867、0.147、0.148、0.176 秒，新版为 0.087、0.086、0.098、0.087 秒；中位数分别约 0.162 与 0.087 秒。新版只枚举 1002 个条目、读取 1000 个文件，没有进入排除目录。初版曾因每次按文件上限读取导致小文件分配开销增加，测得约 0.502 秒；改成最多 64 KiB 分块读取后得到上述结果。


0.3.0 的文件排序借鉴 [Joplin 的离散标题优先规则](https://joplinapp.org/help/dev/spec/search_sorting/)，独立实现字段优先级和有界候选保留。新增检查覆盖遍历顺序反转、重复日志、元数据预览截断、仅文件名命中、解码后的标题与标签、超时／取消保留、完整性标记和 Unicode 摘要位置。真实 MCP 与安装后命令验证文件模式参数及保存后按标题找回笔记。

生成资料集验证：

```powershell
python scripts/local_ranking_benchmark.py --output local-ranking.json
```

脚本生成 1,000 份笔记：999 份正文反复提及关键词，另 1 份在标题中匹配；交替运行 `lines` 和 `files`，每种查询三轮，最多返回 5 条。2026-10-04，在 Windows / Python 3.12.12 / F 盘样本中，“asyncio”和“取消”的默认模式都返回同一文件的 5 行，未返回专题笔记；文件模式均将专题笔记排在首位，返回 5 个不同文件，完整检查全部 1,000 份后标记展示截断。

开启 tracemalloc 时，默认模式耗时约 0.0006–0.0112 秒，文件模式约 0.522–1.156 秒；文件模式的 Python 跟踪分配峰值约 99.4 KiB（不是整个进程工作集）。测量包含分配跟踪开销，结果仅说明这个生成样本中的检索差异与扫描成本，不能作为真实资料库相关性或普遍性能的保证。

0.4.0 的多词条件参考 [Joplin 的全部词／任一词查询](https://joplinapp.org/help/apps/search/)，本项目独立实现有界扫描与逐词证据，保留子串匹配，不引入它的 FTS 索引、分词和查询语法。回归覆盖跨行／跨字段条件、缺词排除、any 的部分匹配、排序层级、中文与代码标点、casefold 去重、逐词列号、资源上限、更新／删除、筛选与取消；真实 MCP 和独立安装验证跨标题与正文找回笔记。

生成资料集比较脚本：`python scripts/local_terms_benchmark.py --output local-terms.json`。它创建 1,000 份笔记，仅 1 份同时含 `asyncio` 与 `取消`，其他 999 份各含其中一个词；对两种词序交替执行 `literal`／`all`／`any` 各三轮，核对完整扫描、命中文件数与逐词证据，并记录耗时和 Python 跟踪分配峰值。这是条件语义与扫描成本实验，不是实际资料库相关性评测。

2026-10-04，Windows／Python 3.12.12／F 盘实测：上述三种模式分别发现 0、1、1,000 份匹配文件，`all` 的唯一结果正是跨标题／正文的目标笔记，两种词序结果一致。开启 tracemalloc 时各六轮耗时范围为 `literal` 0.351–1.415 秒、`all` 0.435–0.573 秒、`any` 0.595–0.833 秒；第一轮包含冷缓存影响，不能用这些范围断言多词模式更快。Python 跟踪分配峰值最高约 493.3 KiB，不是进程工作集，也不代表 16 词或返回 1,000 条时的最坏开销。全部本地回归为 308 项，其中 307 通过、1 项因 Windows 符号链接权限跳过。
