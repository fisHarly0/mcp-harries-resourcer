# HTTP 客户端复用

MCP 服务运行期间，搜索和网页读取从进程内池中独占借用 HTTP 客户端，结束后归还。下次操作优先使用最近归还的客户端，省去反复初始化，并在 HTTP 协议、服务器和代理允许时复用 TCP/TLS 连接。

实现依据：[HTTPX 异步客户端复用建议](https://www.python-httpx.org/async/)及[客户端连接池说明](https://www.python-httpx.org/advanced/clients/)。工具参数、返回结构、限速和正文缓存规则保持原样。

## 生命周期与会话状态

- FastMCP 生命周期启动池，正常退出时关闭空闲和活动客户端，并等待正在进行的关闭任务。
- 一个客户端同一时刻只借给一个操作作用域。一次多查询搜索中的不同查询分别借用；一次批量正文读取中的页面共享该批客户端，保持原来的作用域。
- Cookie 在作用域内正常工作，包括同次请求流程的跳转；归还时全部清空，不跨独立调用保留网站会话。
- 取消一个调用不会关闭另一个调用借用的客户端。网络响应和子任务先完成取消清理，再归还客户端。
- 在没有启动 MCP 生命周期的环境里直接调用 Python 工具函数时，使用临时客户端，用完即关闭，不跨事件循环保留连接。
- 默认的代理环境变量、证书校验和超时设置仍由 HTTPX 处理。修改环境或证书配置后应重启服务，已创建客户端不会自动重新读取配置。

## 资源边界

| 项目 | 当前设置 |
|---|---|
| 最多保留空闲客户端 | 5 个；归还超额时关闭最早归还者 |
| 客户端空闲回收 | 60 秒未再次借出，定时关闭，不需要等待下一次调用 |
| 每个客户端最大连接数 | 10 |
| 每个客户端最大空闲保活连接数 | 5 |
| HTTPX 连接保活期限 | 30 秒；过期连接在后续 HTTP 操作或客户端关闭时释放 |

池限制的是**空闲保留量**，不是所有活动调用的并发上限。没有可用空闲客户端时会创建新客户端，不新增借用等待队列；已有的正文并发限制、搜索限速和时间预算继续生效。服务退出、空闲淘汰和取消期间的关闭任务都会被回收。

初始化仍是同步操作，首次借用或并发峰值需要创建新客户端时仍有开销。正文仍按页启动独立解析进程，未引入常驻解析工作进程。连接是否真正复用还取决于对端、HTTP 版本、响应体是否完整消费、代理以及保活期限；不能承诺每次都使用同一连接。

## 测量与验证

2026-10-04，在 Windows + Python 3.12 上与 `609c6ce` 对比，使用相同解释器、固定技术文章 HTML、本地 HTTP/1.1 服务和真实 MCP stdio 子进程。回环地址显式绕过代理，关闭抓取限速，连续强制刷新 4 次，确保没有用正文缓存代替网络请求。

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 第一次读取 | 0.785 秒 | 0.700 秒 |
| 后三次读取中位数 | 0.718 秒 | 0.497 秒 |
| 实际 HTTP 请求数 | 4 | 4 |
| 目标服务器看到的连接数 | 4 | 1 |

这是本机单次受控样本，不代表所有网络环境的提速比例。解析耗时仍约 0.42–0.50 秒；这轮主要减少客户端初始化及连接建立开销。

回归测试覆盖独占借用、作用域内 Cookie 正常使用、跨调用清理 Cookie、空闲数量上限、无后续请求时的定时回收、取消借用、重复取消期间等待关闭。真实 MCP + 本地 HTTP/1.1 测试还验证两次刷新共用连接、Cookie 不跨调用、服务退出后连接关闭。
