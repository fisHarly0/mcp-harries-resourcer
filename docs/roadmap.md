# 持续优化路线

目标：吸收同类工具的成熟设计，让搜索、阅读、资料保存和找回更可靠、更易用。以下是当前实施顺序，不是能力承诺或已经完成的清单。

## 当前基线

- 已有 8 个工具：搜索、多查询、中文站点搜索、单页/批量正文、调研资料包、Markdown 保存和本地检索。
- 已实现中文优先 Bing / 其他优先 DuckDuckGo、失败诊断、进程内限速、TTL/LRU 缓存、并发下载复用。
- `87e47a5` 已发布；50 项测试在 Windows / Linux、Python 3.10 / 3.12 上通过。

## 已发布：按需阅读与可靠续读

状态：已实现；本地 66 项测试和真实 MCP 联网分页/刷新验证通过，跨平台结果以 [Actions](https://github.com/fisHarly0/mcp-harries-resourcer/actions/workflows/tests.yml) 为准。

- `fetch_page` 增加字符偏移、下一页位置、原文长度，复用完整正文缓存。
- 增加单次 `refresh`，不必关闭整个服务的缓存。
- 读取时提供正文哈希版本；携带上次版本续读，发现变化就要求重读。
- 单页、批量和调研支持 JSON 字符串输出，保留来源、抓取时间、缓存状态和各页错误。
- 调研资料包增加正文总字符预算；预算用尽的页面仍保留来源和续读入口。
- 批量重复 URL 只抓取一次，包含强制刷新场景。

验收：分页重组必须等于完整正文，续读命中缓存不新增请求，刷新内容必须可见，版本变化不能拼接旧文，正文预算不能超额。需要单元测试、真实 MCP 子进程和跨平台 CI 证据。

本轮实测：真实 stdio 子进程读取 Python 官方 asyncio 文档，先读前 100 字符、再续读 100 字符，两段拼接与完整正文前 200 字符相同。续读未新增 HTTP 请求；`refresh=true` 重新抓取成功。本地 HTTP 场景验证正文变化会触发版本不匹配错误。

参考：[DuckDuckGo MCP Server](https://github.com/nickclyde/duckduckgo-mcp-server) 的分页、缓存与上下文控制。实现独立编写，保留本项目已有参数和默认文本输出。

## 已发布：搜索来源控制与合并

已实现包含／排除域名校验、可选双引擎交替合并、规范化 URL 去重、引擎原始排名与查询来源保留、搜索 JSON。中文站点快捷搜索现在会实际检查返回域名；调研只抓取通过筛选的结果。

本地 85 项测试通过，包含真实 MCP 协议；固定中英文联网查询发现英文官方来源可用，中文候选被过滤后遇到后备引擎验证限制。过滤有效，但尚无证据证明合并普遍提高相关性，因此保持可选。完整参数、边界和实测见 [搜索说明](search.md)。跨平台发布结果以 [Actions](https://github.com/fisHarly0/mcp-harries-resourcer/actions/workflows/tests.yml) 为准。

## 已发布：网络恢复与有界下载

实现有限重试、Retry-After 秒数／日期与跨调用等待期、流式传输和解压大小上限、每次跳转限速与跳转上限、覆盖重试与等待的异步总时限。错误响应和跳转体不下载，失败不会缓存部分正文。

本地 106 项测试通过，包含真实 MCP + 本地 HTTP 故障场景；真实联网读取 Python 官方文档及搜索可用。完整边界见 [网络说明](network.md)。该批仅实现单页／单引擎边界，整批控制在下面一批补充。

## 已发布：整批截止时间与部分结果

多查询搜索、批量正文和调研增加 `time_budget_seconds`，默认 120 秒。调研搜索与抓取共用截止时间；到时保留已完成引擎结果与正文，区分已中止和未开始项，等待取消清理后返回。每批只建立最多 5 个工作任务；重复 URL、缓存、来源记录和正文字符预算继续生效。

本地 123 项测试通过，包含真实 MCP 协议、局部 HTTP 慢响应、跨调用共享下载与取消检查，以及 Windows 计时精度导致的跨阶段预算边界回归。真实联网调研在 20 秒预算内完成 3 条来源和 2 篇正文抓取。参数、JSON 字段和限制见 [整批预算说明](batches.md)。该批之后又补充了下述正文解析隔离；实际返回时间仍包含必要的清理，不能视作严格墙钟保证。

## 已发布：Markdown 与引用

单页、批量和调研增加可选 Markdown 正文，保留标题、代码、表格和 HTTP(S) 链接；增加引用索引、结构统计、提取器版本和简单内容提示。两种格式共享下载与刷新，独立校验正文版本，续读和字符预算按所选格式计算。

本地 145 项测试通过。真实 Python 官方文档检验发现列表内代码被压平，已增加提取前标记和渲染后还原，并补回归样本。实测保留 34 个代码块，格式切换命中缓存、分页可重组全文。实现依据、用法和边界见 [Markdown 与引用](content.md)；跨平台结果以 Actions 为准。

## 已发布：正文解析隔离与取消

正文提取移入按页创建的独立进程，默认同时最多 2 页、每页解析预算 20 秒，单页和整批预算继续覆盖解析。实现启动期间取消、重复取消、管道排空和进程回收；失败不缓存，Windows 虚拟环境直接管理实际解释器。

该批本地 158 项测试通过，覆盖真实 MCP 取消通知、解析进程回收，以及 Python 3.10 重复取消导致外层提前返回的回归。约 1 MiB 的复杂 HTML 样本已验证主循环响应与进程退出。资源测量、配置和限制见 [解析说明](parsing.md)。搜索结果页解析隔离和 OS 级内存额度仍未实现，进度通知在下面一批补充。

## 已发布：MCP 进度反馈

六个联网工具增加按请求隔离的进度通知，按已结束查询或网页计数，区分失败与成功；调研搜索期间总量未知，搜索结束后才给出实际总量。整批中止项不补到完成，取消后停止发送。通知合并、限频、发送限时，发送失败不影响正文结果。客户端需主动请求进度，完整规则见 [进度说明](progress.md)。

本地 168 项测试通过，包含真实 MCP 通知、并发请求隔离、取消和超时场景。真实联网批量读取两篇 Python 文档时收到 `0/2 → 1/2 → 2/2`；跨平台结果以 Actions 为准。

## 已发布：HTTP 客户端复用

先测得本机重复客户端初始化成本高于短页解析，再实现服务生命周期内的独占借用、空闲复用、Cookie 清理与定时回收。保留最多 5 个空闲客户端，60 秒到期关闭；直接调用函数时使用临时客户端。真实 MCP 本地短页刷新对比中，后续读取中位数从约 0.72 秒降至 0.50 秒，4 次请求使用的连接从 4 条降至 1 条。完整测量条件与边界见 [客户端说明](clients.md)。

本地 177 项测试通过；真实联网的分页、缓存续读和强制刷新也通过。连接复用测试使用本地 HTTP/1.1 并显式绕过代理，避免把代理侧重连误判为客户端没有复用。

## 已发布：本地资料筛选与有界扫描

本地检索增加集合、全部标签和来源域名筛选、纯筛选浏览与 JSON。遍历前剪枝默认排除目录，跳过符号链接／目录联接；UTF-8 严格解码、分块读取、文件大小、条目数和协作式时限共同控制扫描，未完成和跳过原因明确返回。扫描移入线程，取消时通知停止并等待清理。每次读当前文件，修改与删除无需索引刷新。

已补保存到检索的真实 MCP 流程和边界测试；生成目录基准中 1000 份笔记与 10000 个排除文件命中一致，四轮中位数由旧方式约 0.162 秒降至 0.087 秒。这只反映本机 Windows／F 盘样本。实现依据、测量与限制见 [本地检索说明](local-search.md)，跨平台发布以 Actions 为准。

增加 `pyproject.toml`、版本记录、`mcp-harries-resourcer` 命令和模块启动方式。生产模块移入独立包，保留根目录 `server.py` 的旧启动兼容，解析子进程从包内实际位置启动。依赖范围继续与 `requirements.txt` 共用，不改变笔记目录、格式或 MCP 工具协议。

验证从源码包构建 wheel、在全新虚拟环境安装并检查依赖，随后从仓库外目录启动真实 MCP，覆盖正文解析、Markdown、笔记保存与筛选；CI 在原有四组系统／Python 组合中加入安装验证。Git 来源的 `uvx --from` 用法、更新与固定提交见 [安装说明](installation.md)。

## 已发布：搜索质量证据与文本修正

固定检索案例扩展到 asyncio、React useEffect、FastAPI 依赖注入的中英文查询，分开记录域名约束和预期专题页命中。提供按语言／策略汇总、参考页首个排名、整批预算、重复运行、逐轮保存和公开结果记录。修复行内高亮导致标题单词粘连及摘要标点空格的问题。

本机 12 次搜索中只有 2 次命中预期专题页，域名约束没有发现违规；实测未支持将合并策略设为默认。Bing 域名与语言参数对照也未改善这组参考页命中。下一步后端／策略改进应沿用这组案例并扩大样本，避免把官方首页或 HTTP 成功算作相关资料命中。详见 [搜索质量验证](search-quality.md)。

## 已发布：可选 SearXNG 后端

四个搜索相关工具增加显式后端选择和实例地址配置。独立 JSON 适配器保留聚合排名、上游引擎和部分失败，复用域名校验、去重、限速、下载边界、整批预算和取消清理；配置错误或实例故障不隐式切回内置搜索。JSON 增加后端和实际策略字段，已有调用默认行为保持不变。

验证使用模拟响应、本地 HTTP 与真实 stdio MCP，涵盖四个搜索工具、正文读取及质量报告脚本。用户目前没有可用实例，因此真实 SearXNG 可用性、中文覆盖与目标页命中尚未验证，不将协议测试算作搜索效果提升。部署或获得实例后，用相同案例对照内置后端，再决定后续策略。配置与限制见 [SearXNG 接入](searxng.md)。

新增固定结构样本和独立 CommonMark/GFM 检查，验证实际渲染树；真实 MCP 覆盖该样本的缓存、刷新和分页。Python asyncio 文档前后对照保留全部 34 个代码块内容与 117 个链接，并恢复提取后代码与条目的层级关系。方法、单次开销和仍未解决的复杂布局见 [正文说明](content.md)。

## 已发布：表格行组、标题和数据列

修复实测中的 rowspan=0 左移、跨行组 rowspan 右移、caption 重复表头分隔线和无表头表格无法渲染的问题。使用空白表头保留数据行，补齐列宽，保留表格标题与引用；正文提取器选中的列表／定义项内表格恢复到原条目。

验证依据是独立 Markdown 渲染后的完整单元格矩阵和真实 MCP 的刷新、缓存与分页结果。普通合并单元格采用空位网格，未宣称复现浏览器的跨格边框；跨度上限、嵌套表格和块级单元格内容仍有边界。详见 [Markdown 正文与引用](content.md)。

## 已发布：搜索 HTML 解析隔离

合成搜索页证实同步解析会延迟整个 MCP 主循环。Bing／DuckDuckGo 现在复用已有的可取消解析进程管理，与正文共享名额和预算；同一 HTML 只构建一次树。解析失败保留诊断并按原有策略降级，主动取消与批量截止回收进程，已完成引擎结果继续可用。

已补共享排队、CPU 忙碌、进程与协议失败、重复取消、真实 MCP 部分结果及安装后解析验证。离线基准可复现，并明确短页启动成本与 SearXNG JSON 仍在主进程的边界，详见 [解析隔离](parsing.md)。

## 已发布：网页编码与中文内容

复现仅在 meta 中声明 GBK 的页面被 HTTPX 默认当作 UTF-8 读取、造成标题与正文乱码的问题。原始字节现在进入解析进程，按 BOM、HTTP、有限 meta 扫描确定编码。正文 JSON 保留编码选择和错误记录；搜索标题与摘要也采用同一解码规则。

验证覆盖常用东亚编码、声明冲突、虚假／无效声明、1024 字节边界和损坏字节，并通过真实 MCP 检查中文代码、引用、缓存和分页。安装验证同步使用页面内声明的 GB18030 样本。未加入统计编码猜测，Python 编码器与完整浏览器字符映射仍有差异，详见 [网页编码](encoding.md)。

## 已发布：本地文件排序与命中上下文

复现同一日志的多行命中占满结果上限、长行预览看不到关键词的问题。新增可选文件模式，每份文件一条，以有效标题、标签、文件名、全文命中决定优先级；默认模式保留按行提前返回。摘要改为关键词附近的原文切片，保留 Unicode 字符列号。

文件模式在预算内继续扫描，用有界候选集合保留前 N 份，分别报告扫描与展示的完整性。已加入重复日志、顺序反转、字段匹配、筛选、超时／取消和真实 MCP 验证；千份生成资料集对比显示找回差异及额外读取成本，详见 [本地检索](local-search.md)。

## 本批：新版 Python 与 CI 兼容性

保留 Python 3.10／3.12 检查，增加普通 CPython 3.14 的 Windows／Linux 组合，每组继续运行完整测试、源码包与 wheel 构建及安装后真实 MCP 流程。更新 checkout／setup-python 至 Node 24 运行时的正式版本并固定提交 SHA，避免继续依赖已弃用的 Node 20。版本依据见 [checkout v7.0.1](https://github.com/actions/checkout/releases/tag/v7.0.1) 和 [setup-python v7.0.0](https://github.com/actions/setup-python/releases/tag/v7.0.0)。

本地 Windows／Python 3.14.8 已完成 290 项测试，其中 289 项通过、1 项因符号链接权限跳过。未发现需要修改运行时代码的兼容问题；自由线程构建、PyPy 和其他未列出的平台不在本次验证范围。各提交的六组跨平台结果以 Actions 为准。

## 实施原则

每一批先确认真实缺口和外部设计，再独立实现、补行为测试、更新文档并推送。默认轻量、免搜索 API Key 的体验保留；付费服务和额外后端按需配置。外部项目的 README 不等于本项目的实测证据，未验证的能力不写成已支持。

这一目标持续推进，不因某一批测试通过就宣布全部完成。
